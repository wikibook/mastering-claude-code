# Claude Opus 5 업데이트 (2026년 7월)

> **요약:** 2026년 7월 24일, Anthropic이 Claude Opus 5를 공개했습니다. 가격은 Opus 4.8과 동일한 입력 $5 / 출력 $25인데, 에이전트 성능 벤치마크인 Frontier-Bench 점수는 18.7% → 43.3%로 2배 넘게 올랐습니다. 이 문서는 책 출간 이후의 변경 사항을 보충합니다.

- **관련 장:** 2장(클로드 코드 기초), 4장(고급 활용법), 5장(풀스택 워크플로)
- **작성일:** 2026-07-25
- **모델 ID:** `claude-opus-5`

---

## 1. 한눈에 보기

| 항목 | 내용 |
|------|------|
| 출시일 | 2026년 7월 24일 |
| 모델 ID | `claude-opus-5` |
| 가격(표준) | 입력 $5 / 출력 $25 (100만 토큰당) — Opus 4.8과 동일 |

Anthropic의 최상위 모델인 Fable 5는 입력 $10 / 출력 $50입니다. Opus 5는 그 절반 가격입니다. 단, Opus 5의 Fast 모드 가격은 Fable 5 표준 가격과 같으므로, 빠르게 쓰려면 최상위 모델과 같은 비용을 내는 셈입니다.

## 2. 벤치마크

### 2.1 Frontier-Bench: 43.3% (Opus 4.8은 18.7%)

이번 업데이트의 핵심 숫자입니다. Frontier-Bench는 객관식 정답률이 아니라 **실제 업무를 끝까지 완수했는지**를 측정합니다.

- 74개 과제로 구성
- 코딩뿐 아니라 과학·보안·하드웨어 설계·금융·음악까지 포함
- 과제마다 별도 검증 장치가 합격 여부를 기계적으로 판정

43.3%는 74개 중 약 32개를 완수했다는 뜻입니다. 벤치마크 공개 시점의 최고 점수가 약 34%였으므로 기존 1위를 넘어섰습니다. 다만 절반 이상은 여전히 실패한다는 점도 함께 봐야 합니다. 애초에 그런 난이도로 설계된 시험입니다.

### 2.2 CursorBench: 70.0% (2위)

CursorBench는 Cursor 사내 개발자들이 업무 중 AI에게 실제로 던진 요청을 그대로 모아 만든 벤치마크입니다. 과제 설명을 일부러 짧고 모호하게 두어 실무 상황에 가깝게 구성했습니다. 채점은 정답 여부만이 아니라 다음을 함께 봅니다.

1. 실제 환경에서 코드가 동작하는가
2. 가독성이 좋고 기존 코드 스타일에 맞는가
3. 답을 찾는 데 토큰을 얼마나 썼는가
4. 작업 과정에서 적절하게 행동했는가

| 순위 | 모델 | 점수 |
|------|------|------|
| 1 | Claude Fable 5 | 70.5% |
| 2 | **Claude Opus 5** | **70.0%** |
| 3 | GPT-5.6 Sol | 67.2% |
| 4 | Grok 4.5 | 66.7% |
| 6 | Claude Opus 4.8 | 62.3% |

Opus가 6위에서 2위로 올라갔고, 1위와 차이는 0.5%p인데 가격은 절반입니다. 이 점수는 최대 effort(`max`) 기준입니다.

### 2.3 그 외

- **ARC-AGI 3**(처음 보는 문제 풀기): 2위 모델의 약 3배 점수
- **OSWorld 2.0**(컴퓨터 직접 조작): Fable 5의 최고 기록을 넘었고 비용은 약 1/3
- **Zapier AutomationBench**(업무 자동화): 같은 비용으로 약 1.5배 성공률

> 벤치마크를 볼 때 참고할 점이 있습니다. CursorBench는 Cursor가 자사 데이터로 만든 벤치마크입니다. 구성 방식이 실무에 가까워 참고할 만하지만, 특정 회사가 만든 기준이라는 점은 알고 보는 편이 좋습니다.

## 3. 클로드 코드에서 체감되는 변화

### 3.1 스스로 확인하고 되돌아가 고칩니다

AI에게 작업을 맡길 때 가장 답답한 순간은 틀린 걸 모른 채 계속 진행하는 경우입니다. Opus 5는 자기 작업을 검증하고, 틀렸을 때 되돌아가 수정하는 능력이 강화됐습니다. 여러 단계로 이어지는 긴 작업에서 옆에서 계속 지켜보는 부담이 줄어듭니다.

### 3.2 effort로 비용을 조절합니다

"오래 생각하게 하기"와 "토큰 아끼고 빠르게" 사이를 설정으로 조절합니다(4장 참고). 앞의 CursorBench 70.0%는 `max` 기준이므로, 가벼운 작업이라면 낮춰서 토큰을 아끼는 편이 낫습니다.

### 3.3 시각적 산출물 품질 향상

아티팩트나 인터랙티브 데모처럼 화면으로 확인하는 산출물의 품질이 올라갔습니다.

### 3.4 베타 기능

- 대화 중간에 도구(tool) 정의를 바꿔도 프롬프트 캐시가 유지됩니다
- 차단된 요청은 다른 모델로 자동 연결됩니다

## 4. 안전성

- 자동 정렬(alignment) 평가에서 최근 Claude 모델 중 가장 낮은 2.3점을 기록했습니다. 이 점수는 **낮을수록 좋습니다.**
- 보안 관련 분류기의 과잉 차단이 약 85% 줄었습니다.
- 다만 사이버보안·생물학 연구 영역은 여전히 다른 모델에 뒤집니다.
